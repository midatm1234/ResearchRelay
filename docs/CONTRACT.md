# Implementation contract

Python FastAPI + SQLite (authoritative state), portable Markdown/YAML artifacts, vanilla JS dashboard. A new service retrieves knowledge from the ResearchRelay GitHub SRTD_DT_test branch; saved project bindings take precedence. The explicit offline literature demo processes the verified note snapshot without GitHub or model calls. Publication and live inference remain explicit actions. Participant workers support VS Code editor handoff, Claude CLI, API, command, and manual connections.

`researchrelay.engine.Engine(db_path, project_id='agentic-collaboration')` is the coordination facade. Methods return JSON dictionaries. `.connect()` returns a SQLite connection; `.dashboard(participant='human', since=0)` returns project_id, mode, tasks, artifacts, decisions, events, metrics, changes_since_last_visit. Tasks: id,title,owner,objective,dependencies(list task IDs),input_refs(list {id,version}),expected_outputs,acceptance_criteria,status,attempts,max_attempts,revision_count,claim_token,lease_until,progress,result_ref,blocker. Task status: queued,running,blocked,awaiting_review,completed,failed,canceled. Artifacts stored as {id,version,artifact_type,metadata,body,sha256}. Events have seq,kind,task_id,detail,created_at.

HTTP `/api`: GET dashboard?participant=&since=; GET tasks?owner=&ready=; GET tasks/{id}; POST tasks; POST tasks/{id}/claim {worker_id,lease_seconds}; POST tasks/{id}/heartbeat {claim_token,progress,lease_seconds}; POST tasks/{id}/submit {claim_token,idempotency_key,artifact,completion_notes}; POST tasks/{id}/block {claim_token,reason,question?,options?,evidence?,consequence?}; POST tasks/{id}/cancel; POST tasks/{id}/retry; POST tasks/{id}/reviews {reviewer,verdict:approve|revise, rationale,criteria:list, result_version:int}; GET artifacts/{id}?version=; GET artifacts/{id}/markdown?version=; POST artifacts {metadata,body}; POST meetings {notes,participant}; POST meetings/{id}/approve {tasks: edited proposals}; POST decisions/{id}/resolve {participant,choice,rationale}; POST metrics {participant,kind,value,note}; POST pilot/run (background); POST repository/export; POST repository/import. GET pilot/status. OpenAPI at /docs.

This document records the implementation agreement used during development. The generated OpenAPI document is the API contract for clients. Task input pins supplied by a human override inherited dependency pins by artifact ID; retry accepts an explicit reconciled pin set for queued stale work. Task IDs are at most 96 safe characters; artifact IDs are at most128. Neither permits `..`.

Artifact helper module `researchrelay.artifacts`: `validate_artifact(metadata,body='')->dict`, `render_markdown(metadata,body)->str`, `parse_markdown(text)->tuple[dict,str]`. Schemas in researchrelay/schemas. Artifact metadata common: id,project_id,schema_version='1.0',artifact_type,version>=1,responsible_participant,producing_agent,created_at,updated_at,objective,input_refs,dependencies,expected_outputs,acceptance_criteria,validation_results,unresolved_questions,next_actions,related_files,repository_commits,pull_requests. Defaults permitted in helper; must validate types. Specialized result: task_id,data,code,configuration,environment,evidence,assumptions,limitations. Meeting extraction in `researchrelay.meetings.extract_meeting(notes, participant, project_id)` returns {metadata,body,summary,decisions,proposed_tasks,questions}; explicit vs inferred provenance included; all tasks await human scope approval.

Demo function `run_pilot(engine, repo_path)` calls Engine methods (or API), uses concurrent participant workers, persists everything, and returns a summary with `literature_review`, pinned source-note provenance, publication/access limits, and the next-search decision. No hidden in-memory task queue: workers poll persisted state and Engine reaps expired leases on reads/claims.
