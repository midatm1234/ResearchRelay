# Shared-project implementation contract

Existing FastAPI/SQLite service remains one project per process/database. Multiple authenticated participant tokens map to people; each has its own non-secret agent profile. Execution stays in SQLite; committed GitHub Markdown is the project knowledge record. Preserve macOS support.

Root owns researchrelay/sync.py, API/Engine/config integration and synchronization tests. Providers agent owns providers.py, worker.py, cli.py, docs/agents.md and provider/worker tests. Literature agent owns researchrelay/knowledge.py and its schema/tests, projects/agentic-collaboration Markdown, docs/open-knowledge-format.md. UI agent owns static files, browser smoke updates, README shared-workflow section and docs/shared-projects.md. Coordinate shared files first.

API additions: GET /api/project -> {project_id,participant,repository:{url,branch,knowledge_path}|null,sync:{status,latest_commit,last_checked_at,error,next_action},format_status}; PUT /api/project/repository {url,branch,knowledge_path} coordinator only; POST /api/project/sync -> sync status; GET /api/project/context -> same project fields + documents:[{path,content,sha256,metadata,body,commit}],tasks,artifacts. Context retrieval syncs latest; task claim syncs latest before starting; dashboard includes project and sync and polls remote periodically. Disabled/unconfigured GitHub is supported for existing local pilot.

POST /api/project/publish {base_commit,changes:[{path,content,expected_sha256:string|null}],agent,request_id,message} uses authenticated participant attribution, checks paths within knowledge_path and Markdown metadata, compares touched file versions, preserves unrelated commits, normal push only; returns {status,commit,branch,paths,sync}. Conflict is HTTP409 detail plus conflict paths/latest refs/action. Provider/profile errors are clear without secret values. Profile endpoints GET/PUT /api/participants/me/agent: fields provider (claude-cli|openai-responses|openai-compatible|command|manual),model,base_url,api_key_env,command:list[str], optional allowed_tools. No credential values accepted/stored. GET returns participant + profile. Worker options override own profile; never execute commands server-side.

Knowledge helper contract requested: parse_knowledge(text,project_id=None)->(metadata,body), validate_knowledge(metadata,body='')->dict, render_knowledge(metadata,body)->str. Portable provisional YAML Markdown unless an intended canonical Open Knowledge Format can actually be established. Required id, project_id, schema_version=1.0, artifact_type, version, responsible_participant, producing_agent,created_at,updated_at,format_status=provisional,citations:list,relations:list,provenance object. New knowledge kinds: source_note,literature_index,synthesis,search_log,question,task,decision,review,result. Avoid claiming undefined OKF compliance. Literature date:2026-11-04 America/Los_Angeles. Root supports import of task knowledge with owner/objective/acceptance_criteria/dependencies into SQLite only after scope approved; source notes remain knowledge docs.

Worker project context is fetched before retrieving/claiming work. Store exact context commit + input document hashes in result provenance. Existing result submission still enters awaiting_review. New CLI project commands may retrieve context and publish prepared Markdown with expected_sha256/base_commit; no need model provider credentials server-side. End-to-end pilot uses two participant sessions and a local bare remote for repeatable tests, and a separately documented live SSH GitHub publication on SRTD_DT_test. Exact API names above stable; request root changes if needed.
